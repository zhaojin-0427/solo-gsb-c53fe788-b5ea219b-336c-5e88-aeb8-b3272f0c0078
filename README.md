# 针织版型分码与行程编译台（Knit Pattern Grading & Row Compiler）

本地 Web 应用：录入基准版型（部位尺寸、横纵针密、松量、罗纹/花样循环、缝合关系）与多个尺码目标，
由 **OR-Tools CP-SAT** 对前片、后片、袖片进行**整数针/行联合求解**，再编译成逐行编织指令、
多尺码轮廓叠图，并逐行模拟校验针数守恒、接缝匹配与尺寸偏差。

## 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Python 3.11 · FastAPI · Uvicorn |
| 求解 | OR-Tools CP-SAT（整数规划，带字典序多目标） |
| 存储 | SQLite（项目与求解结果 JSON 持久化，Docker 卷） |
| 前端 | 原生 HTML / CSS / JavaScript（无构建步骤） |

## 一键启动（Docker Compose）

```bash
docker compose up --build -d
```

启动后浏览器访问：

- **应用页面**：http://localhost:8000
- **试织纠偏入口**：求解成功后，右侧结果区第 6 个页签 **「🧵 试织纠偏」**
- API 文档（Swagger）：http://localhost:8000/docs
- 健康检查：http://localhost:8000/api/health

停止：

```bash
docker compose down          # 保留数据卷
docker compose down -v       # 同时删除 SQLite 数据
```

数据库位于容器内 `/data/knit.db`，通过命名卷 `knit-data` 持久化。

### 跨肩阶梯相位配对的校验方式

1. 启动后访问 http://localhost:8000 ，在左侧参数区把「花样垂直循环 Q（行）」设为
   大于 1（如 `4`），勾选「接缝两侧强制花样相位锁定」，点击 **「▶ 联合求解并编译」**。
2. 在右侧 **「逐行模拟校验」** 页签找到
   「接缝相位锁定：袖片袖山收针 ↔ 大身袖窿（曲线收针+肩阶梯）」一项：
   - 表格按**沿缝事件序数**逐对列出：事件对序号、两侧事件类型与**绝对行号**
     （袖山收针 ↔ 袖窿曲线收针；当袖山序数超过袖窿曲线数后，自动改为
     袖山收针 ↔ **肩阶梯**）、相位差 mod Q、✅ 同相 / ⚠️ 错位；
   - 下方另列**未配对事件**（另一侧没有对应序数的多余事件，仅提示，不参与判定）。
3. 也可直接调用 API 核对：`POST /api/solve`（或项目的 `/solve`），返回结果中
   每个尺码 `compiled[*].checks[*]`（`id == "seam_phase_cap_arm"`）含
   `pairs[*]`（`index/row_a/row_b/kind_a/kind_b/phase_diff/ok`）与
   `unpaired[*]`（`side/index/kind/row`）。
4. 若该锁定与结构冲突导致无解，诊断会**只关锁、保留普通 Q 周期规则**复测：
   关锁后可行时，页面把「接缝相位锁定」复选框标红；连 Q 都需取消才可行时，
   标红的是 Q 字段。

## 使用流程

1. 打开页面即载入内置默认样例（女式圆领装袖套头衫，S/M/L 三码，22 针×30 行/10cm）。
2. 在左侧调整针密、容差、罗纹类型、花样水平循环 P（针）/垂直循环 Q（行）、各尺码 12 项尺寸目标。
3. 点击 **「▶ 联合求解并编译」**。首次成功会自动保存项目，后续可从右上角下拉切换历史项目。
4. 右侧分六个页签查看结果：
   - **求解概览**：三层择优目标值、各码关键针/行决策、领罗纹挑针数；
   - **多码轮廓叠图**：前片/后片/袖片的 S/M/L 轮廓叠加（1cm 网格，单位 cm）；
   - **逐行编织指令**：按尺码/衣片/区段筛选，每行给出活针数与“两侧各平收/放针”等指令；
   - **逐行模拟校验**：针数守恒、侧缝/肩缝匹配、袖山-袖窿周长吃势、花样相位、容差报告；
   - **尺寸偏差**：12 项成品指标的目标值→实际值→误差；
   - **🧵 试织纠偏**：见下节。
5. **无解时**：页面顶部列出冲突原因，并把冲突字段在左侧表单中以红框标出
   （如“放宽容差后可行”则容差字段标红；“放宽 Q 后可行”则花样垂直循环字段标红）。

## 试织纠偏（已织前缀锁定的余下行程重排）

试织时实际针数与机编指令常有出入（漏加/多加、意外增减针）。本功能在**不重开整体求解**
的前提下，以“已经织完的部分”为硬约束，只重排**指定衣片未织行**的塑形事件。

### 操作步骤

1. 先正常求解并入库（首次成功求解会自动保存项目与结果）。在结果区打开
   **「🧵 试织纠偏」** 页签。
2. 顶部选择：**绑定求解结果**（项目每次求解都会留下一条历史结果，下拉可切换；
   最近一次排在最前）、**尺码**、**衣片**（前片/后片/袖片）、**已织行数（前缀）**。
3. 点 **「载入前缀登记表」**：系统按该结果原指令逐行预填塑形操作与活针数。逐行核对/修改：
   - 各塑形通道（侧放、袖窿收、肩收、领中心、领缘收；袖片为袖下放/袖山收）；
   - **意外增减针**：该行相对指令多出（正）或缺少（负）的整片针数；
   - **本行后活针**：试织实际值。点 **「按操作+意外针重算活针」** 可按前一行活针
     逐行推算；与手填实际值不一致的行会红底标出（须自洽才能提交）。
4. 确认前缀后点 **「▶ 锁定前缀并重排余下行程」**。CP-SAT 在 10s 内求最优重排；
   页面展示**新旧余下行程对照表**（差异行高亮）、择优指标与全部成稿校验结果。
5. 修订**自动保存并绑定生成它的那一次求解结果**。项目再次求解后，旧结果与旧修订
   都不会丢失，在页签底部「该求解结果的已保存修订」随时展开对照；可单条删除
   （删除修订不影响原结果）。

### 锁定与可重排范围

- **不可改写**：所有已织行；总行数与罗纹/侧区/挂肩/袖山各区段行数；其他衣片；
  大身的侧缝加针行位、肩阶梯行/针数、袖窿曲线收针行位（前后片共用同一套袖窿/肩
  决策，且同一条袖山要缝合前后两片，改动任一侧都会破坏接缝）。
- **大身未织行可重排**：前片—前领中心平收针数、前领深（中心平收行随之移动）、
  前领缘阶梯收针（每事件 1..4 针、单调不增、相邻事件间隔 ≥2 行）；
  后片—后领深（中心平收行）。意外增减针全部由**自由领口缘**吸收：
  `前领中心 + 2×领缘收 = 肩点宽 + 意外针 − 2×肩阶梯收`，两肩活针在末行作为
  领口收口保留，肩缝针/行完全不动。
- **袖片未织行可重排**：袖下加针位置（总量可变，袖肥须守容差带）与袖山收针槽位
 （山型单调不增，每侧总量按 `(袖肥 − 山顶 + 意外针)/2` 补偿）。

### 修订必须通过的硬约束

针数守恒（逐行登记须自洽，意外计入总等式）、成品尺寸容差（领口宽/前领深/后领深/
袖肥，误差口径与求解器一致）、接缝匹配（侧缝/肩缝逐行、袖窿曲线与另一衣片逐行同量、
袖山↔袖窿沿缝事件配对数不少于原方案、曲线周长吃势 ±4 cm）、`seam_phase_lock=true`
且 `Q>1` 时新增袖山事件与袖窿对应事件绝对行号同余 mod Q、关键宽度偶数/P 模数、
领深等段行数为 Q 的倍数。

### 择优（字典序）

1. **改动事件行数**（未织行中相对原指令发生变化的塑形事件行）最少；
2. **针数偏差**（未织行各塑形通道相对原指令的逐行 L1 偏差之和）最小。

### 无解与登记错误

- 登记表不自洽（活针对不上、操作落在错误区段、曲线/肩阶梯被改动等）返回 **422**，
  在对应行红底注明原因，不进入重排；
- 硬约束互相冲突（如前缀锁死后余量不足、意外针为奇数无法成对补偿、容差/相位无法
  同时满足）返回**冲突约束说明**（逐条给出可放松方向，如“放宽容差/关闭相位锁定后
  可行”），**不产出修订、不覆盖原指令**。

## 求解模型说明

### 决策变量（每尺码整数）

- 大身：下摆起针、腋下胸宽、肩宽、领宽（均为整片偶数针）；
  下摆罗纹行、侧区加针行、袖窿行；袖窿曲线收针序列（首次大平收+逐段放缓）、
  肩阶梯次数×每阶针数；前领中心平收、前领单侧阶梯收、前领深、后领深；
- 袖片：袖口起针、袖肥、山顶平收针；袖口罗纹行、袖下加针行、袖山行；
  袖山收针序列（山型单调不增）。

### 硬约束

- 各成品尺寸误差 ≤ 容差（误差按横/纵密精确换算为 1/100 cm）；
- 宽度守恒等式：`胸宽 = 肩宽 + 2×(袖窿收 + 肩阶梯收)`，
  `肩宽 = 领宽 + 2×前领单侧收 + 2×肩活针`，袖片同理；
- 前/后片行结构共用决策 → 侧缝逐行、肩缝阶梯针/行严格匹配；
- 袖山高为袖窿深的 0.70~1.05 倍；事件排布行数可行；
- 罗纹周期（1×1=2 / 2×2=4）与花样 P/Q 模数；
- **接缝花样相位锁定**（`pattern.seam_phase_lock=true` 且 `q_vertical=Q>1` 时启用，
  详见下节）；
- 袖山/袖窿**曲线接缝**按逐段折线长度（CP-SAT element 查表，定点 1/100cm）
  计算周长，吃势偏差纳入目标。

### 接缝花样相位锁定（seam_phase_lock）的校验语义

开关位于参数区「接缝两侧强制花样相位锁定」，仅在纵向花样循环 `q_vertical=Q>1`
时有意义（`Q=1` 时无循环，开关不产生任何约束，模拟报告给出“无需校验”的信息项）。

- **开关关闭（默认，保持原有行为）**：只施加**普通 Q 周期规则**——各结构段行数
  （下摆/袖口罗纹、侧区、袖下加针、袖窿、袖山等）均为 Q 的倍数，保证*片内*花样
  连续；求解器不对接缝两侧事件绝对行号的相位做额外保证，模拟报告也**不再**
  笼统声称“接缝两侧相位对齐”，而是明确注明未做该保证。
- **开关打开**：在普通 Q 周期规则**之上**，按项目 `seams` 缝合关系追加专用约束：
  对每条接缝，把接缝两侧*对应塑形事件*按**沿缝实际发生的序数连续配对**，并将
  每对事件的**绝对行号**（从各自起针行第 1 行计）纳入 Q 模约束。前/后片侧缝与
  肩缝因共用同一套行结构/阶梯决策而天然逐行同相；真正的跨片接缝
  「袖山 ↔ 袖窿」从腋下起缝，配对覆盖**曲线收针与肩阶梯两段**——大身袖窿侧先
  发生曲线收针（首次大平收 + `nah_used` 个槽位），曲线结束后继续发生 `nsh` 个
  肩阶梯事件；袖山侧为首次大平收 + `ncap_used` 个连续收针。自下而上第 j 对
  （j=0 为首次大平收）要求

  ```
  山侧绝对行 = 袖口罗纹行 + 袖下加针行 + j + 1

  窿侧（j ≤ nah_used，曲线段）：
      下摆罗纹行 + 侧区行 + j + 1
  窿侧（j > nah_used，跨肩阶梯段，t = j−nah_used−1）：
      下摆罗纹行 + 袖窿行 − 2×nsh + 2t + 1
  ```

  即袖山序数超过袖窿曲线数之后的收针，与袖窿曲线**之后的肩阶梯**事件同相；
  事件对是否实际存在由 CP-SAT 布尔变量按“两侧都至少有 j+1 个沿缝事件”做条件
  约束，只对两侧都发生的事件对生效（旧实现只约束曲线槽位、报告也只统计曲线
  收针，跨肩阶梯事件完全漏检，可能把不同相的方案误报为全部通过）。

  模拟校验页为每条接缝给出一个校验项，**逐条**报告每个事件对的事件类型
  （袖山收针 / 袖窿曲线收针 / 肩阶梯）、两侧绝对行号、相位差（0~Q−1）与通过
  状态，并在下方表格中列出**未配成跨缝对的多余事件**（另一侧没有对应序数，
  属信息项，不计入通过判定）。校验项的 `pairs`/`unpaired` 字段与求解器约束
  使用同一配对口径，API JSON 中可直接核对。
- **无法满足时**：求解返回不可行，冲突诊断会先尝试“仅关闭该开关（普通 Q 周期
  规则保留）”；若关闭后即可行，则把 `seam_phase_lock` 标为**冲突字段**（前端该
  复选框红框高亮）；若只有连 Q 一起取消才可行，则冲突字段是 `q_vertical`，
  不会误标开关。

> API 与前端字段保持兼容：旧请求中没有 `seams` 时按内置三条默认缝合关系处理；
> 结果中 `pattern.phase_lock` 字段继续保留，同时提供等价的 `seam_phase_lock`。

### 择优顺序（字典序）

1. **最大尺寸误差**最小；
2. **塑形事件总数**最少（收放针阶梯、加针、平收事件）；
3. **相邻尺码跳变**最小（关键针数/行数/事件数的逐码绝对差之和）。

### 编译器与模拟

求解结果由 `compiler.py` 展开为逐行事件表（加针均匀分布、收针靠前分布、
肩阶梯位于挂肩顶部、领心平收位于领深起始行），并重建整片轮廓多边形；
模拟器逐行维护活针数，报告守恒等式、接缝行数/周长、花样周期与容差；当
`seam_phase_lock=true` 且 Q>1 时，额外按缝合关系**逐接缝、逐事件对**核对
两侧塑形事件绝对行号的模 Q 相位差（含事件类型、行号、差值与通过状态），
袖山↔袖窿配对连续覆盖曲线收针与曲线之后的肩阶梯，多余事件列入 `unpaired`。

## 主要 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/default` | 默认样例与字段中文标签 |
| GET/POST | `/api/projects` | 项目列表 / 新建 |
| GET/PUT/DELETE | `/api/projects/{id}` | 项目读 / 改 / 删 |
| POST | `/api/projects/{id}/solve` | 求解+编译并入库（新结果只追加，不覆盖历史） |
| POST | `/api/solve` | 不入库即时求解 |
| GET | `/api/projects/{id}/result` | 最近一次求解结果 |
| GET | `/api/projects/{id}/results` | 项目全部历史求解结果（id/时间） |
| GET | `/api/projects/{id}/results/{rid}` | 读取指定的历史求解结果 |
| POST | `/api/projects/{id}/revisions` | 基于某结果生成试织纠偏修订（可行才入库） |
| GET | `/api/projects/{id}/revisions?result_id=` | 修订列表（可按结果过滤） |
| GET/DELETE | `/api/projects/{id}/revisions/{rev_id}` | 查看 / 删除一条修订（不影响原结果） |

修订与求解结果均以 JSON 存于 SQLite（`results` / `revisions` 表，修订以
`result_id` 外键绑定生成它的结果）；项目重新求解只向 `results` 追加新行，
旧修订与其对照视图永久保留。
